# 工程机器人与英雄机器人底盘功率控制对比

本文记录当前工程机器人框架（`27Zhongzhuang_Chasis`）与英雄机器人框架（`Basic_Third_Hero`）的底盘功率控制实现，便于后续把英雄机器人的功率限制逻辑移植到工程机器人。

本文是源码静态分析结果，未进行实车抓包或功率标定。

## 结论

当前工程机器人框架中已经有功率控制算法的接口和部分计算代码，但没有接入实际底盘控制任务。底盘的速度 PID 输出会直接进入 DJI 电机控制报文。

英雄机器人框架已经把功率控制接入电机控制任务，并将裁判系统功率上限、缓冲能量和超级电容状态合并成底盘功率预算，再对四个 DJI 电机的电流输出进行功率模型限幅。

因此，两套代码的差别不是“算法参数不同”，而是：

```text
工程机器人：功率控制模块存在，但当前未接入输出链路
英雄机器人：功率控制模块已经处于电机输出链路中
```

### 实际电机任务链路

英雄底盘的电机任务中明确调用：

```c
DJIMotorControl();
PowerControl();
```

文件：

```text
chassis/modules/motor/motor_task.c
chassis/modules/motor/power_control.c
```

实际链路为：

```text
底盘速度参考
  ↓
速度 PID
  ↓
计算每个电机的理论功率
  ↓
四个电机功率求和
  ↓
超过预算时计算缩放系数
  ↓
根据功率模型反解允许电流
  ↓
发送 DJI CAN 控制报文
```

### 英雄机器人的功率模型

英雄机器人首先计算每个轮子的理论功率：

```c
A = K1[i] * torque * torque;
B = K2[i] * speed * speed;
C = POWER_COEF * speed * torque * TORQUE_COEF;

power[i] = A + B + C + constant[i];
```

然后只统计正功率：

```c
initial_total_power += initial_give_power[i];
```

当总功率超过限制时：

```c
ratio = chassis_max_power / initial_total_power;
```

每个电机的功率目标先按比例缩小，再通过二次方程反解电流值：

```text
a × current² + b × current + c = 0
```

这样最终发给 DJI 电调的不是原始 PID 电流，而是满足当前总功率预算的电流。

负功率被视为电机回馈或减速产生的功率，不计入正向功率消耗统计。

### 英雄机器人的功率预算来源

底盘应用从裁判系统读取：

- `chassis_power_limit`
- `buffer_energy`
- `power_management_chassis_output`

然后计算当前生效的 `final_power_limit`，最终调用：

```c
SetPowerLimit(final_power_limit);
```

英雄机器人当前还接入了超级电容。超级电容通过独立 CAN 链路提供：

- 当前底盘实际功率
- 超电板可提供的底盘功率上限
- 电容能量百分比限
- 电容能量百分比
- 错误状态

英雄底盘会先根据裁判系统和超级电容计算功率预算，再由 `PowerControl()` 对四个 DJI 电机进行最终限幅。

## 建议的工程机器人移植方案

建议保留工程机器人现有的底盘运动学和 PID，只移植英雄机器人的“功率执行层”。最小改动链路如下：

```text
Chassis PID 输出 output[4]
        ↓
读取四个 DJI 电机速度
        ↓
计算四个电机理论功率
        ↓
与裁判系统功率上限比较
        ↓
功率超限时反解四个电机允许电流
        ↓
Chassis_Motor_SendControl_DJI()
```

建议按以下顺序实施：

1. 先把 `PowerHeatData.chassis_power_limit` 和 `buffer_energy` 接到工程底盘任务。
2. 将英雄 `power_control.c` 中的功率模型改成工程电机数据结构接口。
3. 在 DJI 控制报文发送前完成四电机电流限幅。
4. 用固定功率上限进行台架测试，确认四轮总功率不会超过限制。
5. 再接入超级电容的功率回报和 DCDC 状态。
6. 最后重新标定 `K1`、`K2`、`constant` 和电机转矩系数。

不要只调用工程现有的 `PowerControl_Update()`。它目前只能产生一个总功率预算，不能自动修改 `set_motor_parameter()` 的四个电流参数。

## 需要特别注意的问题

- 裁判系统的功率上限是底盘总功率预算，不是单个电机的电流上限。
- 四个电机应使用同一拍的速度反馈和同一拍的功率预算，避免部分电机使用旧数据。
- 负功率不应简单当作正功率累加，否则减速时会过度限制输出。
- 功率模型系数必须根据实际电机、电调、电源和轮组负载重新标定。
- 超级电容在线不等于可以无限增加功率，必须同时检查回传功率上限、错误状态和输出禁止状态。
- 功率限制应放在最终电流发送之前，不能只限制速度目标；速度 PID 仍可能在负载变化时产生较大电流。
