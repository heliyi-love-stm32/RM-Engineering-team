# 六轴机械臂控制数据报告

> 依据当前工作区源码整理。本文记录软件中可确认的配置与数据流；电机内部控制算法、机械结构零位和现场总线接线关系仍需结合电机手册及实物验证。

## 1. 总览

机械臂控制由 FreeRTOS 任务 `jointFollowAngle` 驱动。控制器数据从 UART7 接收，经裁判/控制器帧解析后更新六轴目标角；任务将目标位置和速度编码为 DM 电机 CAN 指令，同时通过 CAN 中断收集电机反馈并在任务上下文中解码角度、速度、力矩/电流和状态。

```text
控制器
  └─ UART7 Receive-to-Idle → CRC/帧解析 → CtrllerData[28]
       └─ ASCII角度解析 → 零点偏移 → 关节极性 → J2/J3补偿
            └─ Target_Point[6]
                 └─ Joint_Move → DM位置/速度帧 → FDCAN1/2/3 → 关节电机

关节电机反馈 → FDCAN FIFO0中断 → 按反馈CAN ID更新消息缓存
             → jointFollowAngle刷新解码 → 当前角度/错误/温度等状态
```

## 2. 任务启动与主循环

1. `main()` 初始化 FDCAN1/2/3 后调用 `can_sys_init()`，启动三个 FDCAN 外设、配置标准 ID 过滤器并启用 FIFO0 新消息中断。
2. FreeRTOS 创建 `jointFollowAngle`、`Referee_Task`、`auto_get_task` 和复位后台任务。`Referee_Task` 将 UART7 注册为控制器链路，任务循环每 2 ms 拉取并解析控制器/裁判数据。
3. `jointFollowAngle` 初始化六轴和目标点、初始化夹爪，然后等待 100 ms。正常配置下使能全部关节及夹爪；只读配置下失能电机并跳过控制帧发送。
4. 主循环顺序为：发送上一轮目标 → 刷新六轴反馈 → 刷新夹爪反馈 → 保存当前关节角 → 更新夹爪状态机 → 按状态机更新下一轮目标 → `osDelay(1)`。
5. 因 `Joint_Move()` 内部还有四次 `osDelay(1)`，循环实际包含至少五个 1 tick 延时（另加执行和调度时间），不能按注释中的 1 kHz 将实际控制周期视为 1 ms。状态机产生的新目标通常在下一轮 `Joint_Move()` 才发送。

相关实现：[jointFollowAngle.cpp](../source/task/Arm_Task/jointFollowAngle.cpp)、[joint_control_drv.c](../source/task/Arm_Task/joint_control_drv.c)、[main.c](../Core/Src/main.c)、[freertos.c](../Core/Src/freertos.c)。

## 3. CAN ID、端口与电机配置

| 轴/设备 | CAN 端口 | 基础命令 ID | 反馈 ID | 位置/速度模式发送 ID |
|---|---:|---:|---:|---:|
| J1 | CAN3 | `0x01` | `0x11` | `0x101` |
| J2 | CAN3 | `0x02` | `0x12` | `0x102` |
| J3 | CAN2 | `0x03` | `0x13` | `0x103` |
| J4 | CAN2 | `0x04` | `0x14` | `0x104` |
| J5 | CAN2 | `0x05` | `0x15` | `0x105` |
| J6 | CAN2 | `0x06` | `0x16` | `0x106` |
| 夹爪 | CAN2 | `0x07` | `0x17` | `0x107` |

- 位置/速度模式 ID 由 DM 驱动将基础 ID 加上 `POS_MODE`（`0x100`）生成。使能、失能、保存零点等管理命令使用基础 ID。
- 六轴每个电机配置 `PMAX=12.5 rad`、`VMAX=3.0 rad/s`、`TMAX=1.0`；这些参数用于反馈解码，也作为 MIT 模式量化范围。代码注释中仍有 `-45`、`-18` 等旧范围文字，与当前 `VMAX/TMAX` 配置不一致。
- 表中的实际映射由 `joint_control_drv.c` 初始化时设置；头文件中也定义 `can_id[]`、`can_msg_id[]` 常量数组，但初始化代码使用 `0x01 + index`、`0x11 + index` 直接赋值。
- 夹爪初始化设置 CAN2、基础 ID `0x07` 和反馈 ID `0x17`。打开/关闭/特殊位置分别为 `0.0/0.8/0.4 rad`，速度 `1.5 rad/s`。

相关实现：[joint_control_drv.c](../source/task/Arm_Task/joint_control_drv.c)、[joint_control_drv.h](../source/task/Arm_Task/joint_control_drv.h)、[ee_control_drv.c](../source/task/Arm_Task/ee_control_drv.c)、[ee_control_drv.h](../source/task/Arm_Task/ee_control_drv.h)、[motor_DM.h](../source/module/motor/motor_DM/motor_DM.h)。

## 4. CAN 收发与电机帧

### 4.1 CAN 层

- CAN1、CAN2、CAN3 使用标准 ID 过滤器，范围配置为 `0x000–0xFFF`，匹配的帧进入 FIFO0。
- FIFO0 中断按 FDCAN 实例选择 CAN1/2/3 接收回调；回调从 FIFO 读取帧，再按“端口消息列表 + 标准 ID”查找电机反馈消息并更新数据、长度和接收计数。
- 电机初始化时将反馈消息对象注册进对应 CAN 端口列表；发送由 `can_msg_send_classical()` 选择相应 FDCAN 句柄，再通过 HAL 加入发送 FIFO。
- 实际电机控制使用经典 CAN 标准数据帧，不是 CAN FD 帧。

### 4.2 控制命令

- 位置/速度命令：8 字节，前 4 字节为位置 `float` 原始字节，后 4 字节为速度 `float` 原始字节，CAN ID 为基础 ID + `0x100`。
- 使能命令：8 字节 `FF FF FF FF FF FF FF FC`；失能结尾为 `FD`；保存零点结尾为 `FE`；清错结尾为 `FB`。这些命令使用基础 CAN ID。
- 虽然驱动还提供 MIT 位置/速度/Kp/Kd/力矩控制接口，但 `Joint_Move()` 当前调用的是位置/速度接口；当前六轴常规控制路径未调用 MIT 接口。

### 4.3 反馈解码

`Motor_DM_Refresh()` 从反馈帧解码：

| 字段 | 反馈字节 | 处理 |
|---|---|---|
| 错误码 | `data[0]` 高 4 位 | 写入 `error_code` |
| 角度 | `data[1:2]` | 16 位无符号值映射到 `[-PMAX, PMAX]` |
| 速度 | `data[3]` 与 `data[4]` 高 4 位 | 12 位值映射到 `[-VMAX, VMAX]` |
| 力矩/电流 | `data[4]` 低 4 位与 `data[5]` | 12 位值映射到 `[-TMAX, TMAX]` |
| 温度 | `data[6]`、`data[7]` | 保存两者中的较大值 |

该固件负责接收并解码反馈，但常规关节运动没有用这些反馈在 MCU 上计算位置 PID 输出；位置/速度目标帧直接交给电机。

相关实现：[can_bsp.c](../source/bsp/can/can_bsp.c)、[can_api.c](../source/bsp/can/can_api.c)、[motor_DM.c](../source/module/motor/motor_DM/motor_DM.c)。

## 5. 控制器数据传输与角度解析

### 5.1 UART 接收

- `Referee_Task` 将 UART7 用作图传/自定义控制器链路，并注册 Receive-to-Idle 接收。
- UART7 接收回调先将 DMA/接收缓冲区数据复制到 shadow buffer，再重启接收并调用控制器回调。
- 控制器解析器在环形缓冲区中查找帧头，验证 CRC8/CRC16 并检查帧长度；命令码 `0x0302` 被识别为自定义控制器帧。
- `CtrllerData` 长度为 28 字节；当前命令分支从接收帧偏移 7 处复制 27 字节到 `CtrllerData`。第 28 字节不是该分支的有效输入字段。

### 5.2 当前 ASCII 格式和角度换算

`Parse_ControllerData_To_CtrllerRadian()` 按字符数字转换：

1. J1–J5 分别读取 4 位十进制数，输入索引为 `0–19`；J6 读取 5 位，索引 `20–24`。
2. 数值先乘 `0.001`，得到弧度量级。
3. J1、J2、J4、J5 减去 `π`；J3 减去 `π + 0.2`；J6 减去 `2π` 后再乘方向符号。方向由字节 26 决定：字符 `'0'` 为正，其他值为负。
4. 字节 25 用作夹爪按键状态；变化时调用 `endEffector_Toggle()`。
5. `CtrllerData_To_InputRadian_Converter()` 再乘关节自定义极性映射：`[-1, +1, -1, -1, -1, -1]`。
6. 控制跟随处理额外给 J2 加 `0.20 rad`、J3 加 `0.5 rad`，随后将六轴目标角及速度写入 `Target_Point`。

当前自定义控制器的默认速度为 `[2.0, 1.3, 2.0, CUSTOM_DEFAULT_VELOCITY, 3.0, 3.0] rad/s`；其中宏 `CUSTOM_DEFAULT_VELOCITY` 当前定义为 `1.0 rad/s`。

### 5.3 “角度映射”模块边界

`source/module/control/KinematicSolution/AngleMapping/angleMap.c` 中的 `RefFrame_Transform_Calc()` 是二维向量坐标系旋转：旋转 `x/y`，保持 `wz` 不变。当前机械臂跟随代码没有调用它。机械臂实际使用的是上述输入角偏移、J6 方向处理、自定义极性和 J2/J3 补偿；未在这条路径中发现机械臂正/逆运动学或笛卡尔到关节的几何映射。

相关实现：[uart_bsp.c](../source/bsp/uart/uart_bsp.c)、[referee_api.c](../source/module/refereeSys/referee_api.c)、[arm_handle.c](../source/task/Arm_Task/arm_handle.c)、[angleMap.c](../source/module/control/KinematicSolution/AngleMapping/angleMap.c)。

## 6. PID 与闭环边界

- 仓库有通用位置式与增量式 PID：`PID_Calc_Pos()`、`PID_Calc_Add()`，包含积分限幅和输出限幅。
- 当前 `source/task/Arm_Task` 没有调用 `PID_Init()` 或上述 PID 计算函数。机械臂常规控制流程是计算目标值并调用 `PosSpeed_CtrlMotorDM()`，并非 MCU 软件 PID 闭环。
- 电机反馈角度虽被解析并保存在 `Current_Radian[]`，但此主循环未用它更新位置误差或位置命令。
- 仓库中出现的 PID 使用例包括底盘功率控制，不能据此推断为机械臂 PID。

相关实现：[PIDtool.c](../source/module/control/PID/PIDtool.c)、[PowerControl.c](../source/module/control/PowerControl/PowerControl.c)、[jointFollowAngle.cpp](../source/task/Arm_Task/jointFollowAngle.cpp)。

## 7. 模式与目标点调度

| 模式/路径 | 当前行为 |
|---|---|
| 空闲 | `TRAJ_DEBUG=0` 时状态机转入自定义控制器跟随 |
| 控制器跟随 | 解析 UART 输入，映射关节角，发布六轴目标与速度 |
| 自动 | 自动取放任务按 5 ms 步进更新轨迹目标 |
| 启动/安全/零位/起身 | 发布各自预设位置和速度 |
| 冻结 | 将所有目标速度置零 |
| 轨迹模式 | `Arm_Traj_Handle()` 当前为空实现；该模式本身不启动轨迹 |
| 夹爪 | 独立状态机在打开、关闭和特殊位置模式间运行，按钮变化触发开/关切换 |

`Joint_Move()` 的发送顺序为 J2、J5；J3、J1；J4；J6。相邻批次间有 1 tick 延时，最后一批后也有 1 tick 延时。

## 8. 源码核对发现与建议复核项

以下是由当前实现直接可见的边界/风险，不代表已经通过实机测试确认故障：

1. **关节限位未进入常规下发路径。** `Joint_Pos_Limit()` 和每轴限位表虽已定义，但控制器跟随发布目标前没有调用限位函数；位置/速度帧也直接发送原始 `float`。应确认上位控制器范围及电机自身限位是否足够。
2. **J3 限位配置需检查。** `joint_pos_limit_min_map[2]` 与 `joint_pos_limit_max_map[2]` 当前都为 `3.0f`；即便后续启用限位函数，该轴也会得到退化的限位区间。
3. **夹爪反馈解码量程未赋值。** `endEffector_motor_init()` 配置了端口和 ID，但没有设置 `tmp.PMAX/VMAX/TMAX`；与此同时主循环持续调用 `EndEffector_Motor_Refresh()`，该函数会以这些量程解码反馈。建议明确夹爪电机量程并初始化。
4. **首帧反馈有效性未门控。** 电机结构体由 `pvPortMalloc()` 分配；当前初始化路径未见结构体清零，也未见在收到首帧前禁止刷新/使用反馈。建议确认反馈消息缓存初值和首次接收状态管理。
5. **控制器负载长度需匹配校验。** CRC 帧解析器验证了整帧，但 `0x0302` 分支固定复制 27 字节负载；建议确认该命令的实际 payload 长度始终不少于 27 字节，或在复制前显式校验命令负载长度。
6. **控制周期应按实际调度评估。** 关节发送函数内的延时使任务循环至少消耗 5 个 RTOS tick；如需 1 kHz 关节命令刷新，应重新测量并调整分批策略/周期。
7. **源码注释存在量程漂移。** DM 反馈解码注释中的速度、力矩范围与实际配置 `VMAX=3.0`、`TMAX=1.0` 不一致，建议统一注释和参数定义。
