# 机械臂增加运动轨迹技术文档

## 1. 文档目的

本文说明如何在当前工程中增加一条新的六轴机械臂关节轨迹，并让它能够被自动轨迹任务触发执行。

本文以新增轨迹 `traj_demo` 为例。示例动作如下：

1. 从安全起始姿态缓慢抬起机械臂。
2. 移动到目标姿态，夹爪保持打开。
3. 夹爪关闭，停留一段时间。
4. 回到安全姿态，夹爪保持关闭。

这里的“轨迹”是关节空间轨迹，不是笛卡尔空间直线轨迹。每一个轨迹点包含六个关节的目标弧度、速度、该段持续时间和夹爪模式。

> 安全要求：第一次测试必须卸下负载，机械臂周围不得有人或障碍物，并准备好断电、急停或进入安全模式的操作。

---

## 2. 当前工程的轨迹执行链

当前工程使用以下控制链路：

```text
触发命令
   |
   v
auto_key_cmd_exec()
   |
   v
auto_get_task()  ---- 5 ms定时器 ----> auto_traj_idx递增
   |
   v
TrajectoryExecutor::update()
   |
   v
Target_Point[6]
   |
   v
jointFollowAngle() ---- 1 ms主循环 ----> Joint_Move()
   |
   v
DM电机位置/速度控制
```

相关代码位置：

| 文件 | 作用 |
|---|---|
| `source/task/auto_get_task/auto.h` | 定义轨迹点和 `TrajectoryExecutor` |
| `source/task/auto_get_task/auto_traj_data.h` | 声明轨迹数组和数组长度 |
| `source/task/auto_get_task/auto_traj_data.cpp` | 保存实际轨迹数据 |
| `source/task/auto_get_task/auto_get_task.cpp` | 初始化执行器、注册命令、切换轨迹 |
| `source/task/auto_get_task/auto_get_timer_init.c` | 每 5 ms 推进轨迹索引 |
| `source/task/Arm_Task/jointFollowAngle.cpp` | 1 ms 主控制循环和电机控制 |
| `source/task/Arm_Task/arm_state_machine.cpp` | 根据控制模式调度自动模式 |
| `source/task/Arm_Task/joint_control_drv.h` | 定义单关节目标点结构 |

`CMakeLists.txt` 使用 `file(GLOB_RECURSE ...)` 自动收集 `source` 下的 `.c` 和 `.cpp` 文件，所以新增轨迹通常不需要单独修改 CMake 文件。

## 3. 轨迹数据结构

### 3.1 单关节目标点

定义在 `joint_control_drv.h`：

```cpp
typedef struct target_point_t {
    float target_joint_radian;  // 目标角度，单位 rad
    float velocity;             // 该关节速度，单位 rad/s
} target_point_t;
```

### 3.2 轨迹段

定义在 `auto.h`：

```cpp
struct traj_group_point_t {
    target_point_t q[6];
    uint32_t time;
    gripper_control_mode_t gripper_ctrl;
};
```

每个轨迹段的含义如下：

| 字段 | 含义 | 单位或取值 |
|---|---|---|
| `q[0]` | J1 目标角度和速度 | rad、rad/s |
| `q[1]` | J2 目标角度和速度 | rad、rad/s |
| `q[2]` | J3 目标角度和速度 | rad、rad/s |
| `q[3]` | J4 目标角度和速度 | rad、rad/s |
| `q[4]` | J5 目标角度和速度 | rad、rad/s |
| `q[5]` | J6 目标角度和速度 | rad、rad/s |
| `time` | 当前段持续时间 | ms |
| `gripper_ctrl` | 该段夹爪状态 | `GRIPPER_OPEN_MODE`、`GRIPPER_CLOSE_MODE`、`GRIPPER_SPECI_MODE` |

关节索引约定：

| 数组索引 | 关节 | 常见含义 |
|---|---|---|
| `q[0]` | J1 | 底座旋转 |
| `q[1]` | J2 | 大臂俯仰 |
| `q[2]` | J3 | 小臂俯仰 |
| `q[3]` | J4 | 腕部旋转 |
| `q[4]` | J5 | 腕部俯仰 |
| `q[5]` | J6 | 末端旋转 |

### 3.3 执行时间计算

当前执行器的周期固定为 5 ms。假设轨迹段的 `time` 依次为 1000 ms、2000 ms、1500 ms，则：

```text
第 1 段：索引 0 到 199，持续约 1000 ms
第 2 段：索引 200 到 599，持续约 2000 ms
第 3 段：索引 600 到 899，持续约 1500 ms
```

总时间约为：

```text
总时间 = 所有轨迹段 time 之和
```

注意：`time` 不表示单个关节走完角度所需的实际时间。电机是否能在该段时间内到达目标，还取决于角度差和 `velocity`。

## 4. 增加轨迹前的准备工作

### 第 1 步：确定动作流程

先用纸或表格写清楚每一步动作，不要直接在代码里试角度。至少记录：

| 步骤 | 动作 | J1 | J2 | J3 | J4 | J5 | J6 | 时间 | 夹爪 |
|---|---|---:|---:|---:|---:|---:|---:|---:|---|
| 1 | 安全起始姿态 | 0 | 0.0 | 0.2 | 0 | 0 | 0 | 1500 | 打开 |
| 2 | 到达目标位置 | 0 | 0.7 | 0.9 | 0 | -0.2 | 0 | 3000 | 打开 |
| 3 | 夹取停留 | 0 | 0.7 | 0.9 | 0 | -0.2 | 0 | 1000 | 关闭 |
| 4 | 抬起并回位 | 0 | 0.2 | 0.4 | 0 | 0 | 0 | 2500 | 关闭 |

角度必须以弧度填写。角度换算公式为：

```text
rad = degree * PI / 180
```

例如 90 度约等于 `1.5708f`，180 度约等于 `3.1416f`。

### 第 2 步：确认关节限位和方向

新增轨迹前要对照当前关节配置，确认：

1. 目标角度没有超过软件限位。
2. 目标角度与实际机械方向一致。
3. J3、J6 等存在偏置或方向处理的关节，使用的是轨迹系统已经验证过的角度定义。
4. 轨迹的起点与机械臂当前姿态接近，避免上电后突然大幅运动。
5. 所有速度均为正值且足够小，首次测试建议使用现有轨迹速度的 30% 到 50%。

不要在轨迹数组中使用未经验证的极限角度。对于不确定的角度，先单独发布一个目标点，低速确认方向后再加入完整轨迹。

### 第 3 步：限制轨迹点数量

`TrajectoryExecutor` 中的时间累加数组长度是 30：

```cpp
constexpr uint32_t TRAJ_GROUP_SIZE = 30;
uint32_t time_acc_[30];
```

因此一条轨迹最多使用 30 个轨迹段。超过 30 段必须先扩展执行器的容量，并同步检查 RAM 使用量。

## 5. 第一个代码修改：增加轨迹数据

打开 `source/task/auto_get_task/auto_traj_data.cpp`，在已有轨迹定义附近增加新数组。建议放在文件中已有轨迹数组之后，保持轨迹数据集中管理。

示例：

```cpp
huangjiazhi::traj_group_point_t traj_demo[] = {
    {
        {
            {0.0f, 0.3f},
            {0.0f, 0.3f},
            {0.2f, 0.3f},
            {0.0f, 0.3f},
            {0.0f, 0.3f},
            {0.0f, 0.3f},
        },
        1500,
        GRIPPER_OPEN_MODE,
    },
    {
        {
            {0.0f, 0.3f},
            {0.7f, 0.3f},
            {0.9f, 0.4f},
            {0.0f, 0.3f},
            {-0.2f, 0.3f},
            {0.0f, 0.3f},
        },
        3000,
        GRIPPER_OPEN_MODE,
    },
    {
        {
            {0.0f, 0.2f},
            {0.7f, 0.2f},
            {0.9f, 0.2f},
            {0.0f, 0.2f},
            {-0.2f, 0.2f},
            {0.0f, 0.2f},
        },
        1000,
        GRIPPER_CLOSE_MODE,
    },
    {
        {
            {0.0f, 0.3f},
            {0.2f, 0.3f},
            {0.4f, 0.3f},
            {0.0f, 0.3f},
            {0.0f, 0.3f},
            {0.0f, 0.3f},
        },
        2500,
        GRIPPER_CLOSE_MODE,
    },
};
```

每个数组元素必须有三部分：

```text
{ 六个关节目标点, 当前段时间, 夹爪模式 }
```

常见错误：

- 六个关节少写或多写一个。
- 把角度写成度数，例如直接写 `90`，而不是 `1.5708f`。
- 速度写成负数。
- `time` 写成秒，例如写 `3`，实际会变成 3 ms；应写 `3000`。
- 轨迹数组末尾漏掉分号。

## 6. 第二个代码修改：在头文件声明轨迹

打开 `source/task/auto_get_task/auto_traj_data.h`，增加轨迹数组声明：

```cpp
extern huangjiazhi::traj_group_point_t traj_demo[];
extern const uint32_t traj_demo_size;
```

放置位置可以与其他轨迹声明保持一致。头文件声明的名称必须和 `.cpp` 中的数组名称完全一致。

---

## 7. 第三个代码修改：增加轨迹长度

打开 `source/task/auto_get_task/auto_traj_data.cpp` 文件末尾的长度定义区域，增加：

```cpp
const uint32_t traj_demo_size = sizeof(traj_demo) / sizeof(traj_demo[0]);
```

不要手工填写轨迹点数量。使用 `sizeof` 可以避免增删轨迹点后忘记修改数量。

建议检查以下三项是否同时存在：

```text
1. traj_demo[] 的实际定义
2. auto_traj_data.h 中的 extern 声明
3. traj_demo_size 的长度定义
```

缺少任意一项都可能导致编译错误或链接错误。

## 8. 第四个代码修改：增加触发命令

如果只想在调试模式启动新轨迹，可以暂时把 `auto_get_task.cpp` 中的默认轨迹改为：

```cpp
traj_exec.init(traj_demo, traj_demo_size, 5);
```

如果希望通过按键、遥控器或上层逻辑选择新轨迹，建议增加一个命令枚举。

### 8.1 增加命令枚举

打开 `source/task/auto_get_task/auto_keyboard.h`，添加：

```cpp
CMD_AUTO_TRAJ_DEMO,
```

建议放在自动轨迹命令区域，并用注释写明用途：

```cpp
CMD_AUTO_TRAJ_DEMO,  /* 演示轨迹 */
```

### 8.2 注册命令到轨迹

打开 `source/task/auto_get_task/auto_get_task.cpp`，在 `switch (cmd_req)` 中增加：

```cpp
case CMD_AUTO_TRAJ_DEMO:
    Auto_Switch_Group(traj_demo, traj_demo_size);
    break;
```

`Auto_Switch_Group()` 会完成以下操作：

1. 绑定新的轨迹数组。
2. 保存轨迹段数量。
3. 使用 5 ms 周期。
4. 重新计算累计时间。
5. 将当前段复位到第 0 段。
6. 将轨迹索引清零。
7. 启动自动轨迹定时器。

因此不要在调用命令前手工修改 `auto_traj_idx`，也不要重复启动另一个轨迹定时器。

## 9. 第五个代码修改：从上层触发轨迹

在已有的按键处理、遥控器处理或测试代码中调用：

```cpp
auto_key_cmd_exec(CMD_AUTO_TRAJ_DEMO);
```

触发前必须确保机械臂处于自动模式：

```cpp
Arm_Current_Control_Mode = Arm_Auto_Mode;
auto_key_cmd_exec(CMD_AUTO_TRAJ_DEMO);
```

更推荐由已有的状态切换逻辑统一设置模式，不要在多个任务中同时修改 `Arm_Current_Control_Mode`。当前自动模式的实际执行由 `Joint_Control_Mode_Manager()` 调用 `Arm_Auto_Mode_Handle()` 完成，而轨迹任务通过 `TrajectoryExecutor::update()` 更新 `Target_Point`。

如果只触发命令但系统仍在 `Arm_Custom_Controller_Follow_Mode`，控制器跟随函数可能继续覆盖 `Target_Point`，表现为轨迹不动、跳回手柄位置或动作抖动。

---

## 10. 第六个代码修改：确认任务和定时器已初始化

新增轨迹不需要新增任务，但必须确认系统已经创建并运行以下内容：

1. `auto_get_task()` 任务已经创建。
2. `traj_timer_init()` 已调用并创建 `auto_traj_timer_id`。
3. `jointFollowAngle()` 主任务正在运行。
4. 当前控制模式是 `Arm_Auto_Mode`。
5. 电机已经使能，CAN 通信正常。

自动轨迹定时器的回调只有在自动模式下才会增加 `auto_traj_idx`：

```c
if (Arm_Current_Control_Mode == Arm_Auto_Mode) {
    auto_traj_idx++;
}
```

如果模式不正确，轨迹索引不会推进。

## 11. 编译检查

完成代码修改后，在工程根目录执行：

```powershell
cmake --build build --parallel
```

如果当前构建目录不是可用配置，先执行：

```powershell
cmake --preset Debug
cmake --build build/Debug --parallel
```

重点检查以下错误：

| 错误现象 | 常见原因 |
|---|---|
| `traj_demo was not declared` | 忘记在 `auto_traj_data.h` 中声明 |
| `traj_demo_size was not declared` | 忘记声明长度符号 |
| `undefined reference to traj_demo` | 声明和定义名称不一致，或源文件未被编译 |
| 初始化括号错误 | 六个 `target_point_t` 的大括号层级不正确 |
| 枚举不存在 | 没有在 `auto_keyboard.h` 增加命令 |
| 轨迹不触发但能编译 | 没有在 `auto_get_task.cpp` 的 `switch` 中注册 |

构建成功后建议确认生成了 `.elf`、`.bin` 或工程实际使用的固件文件，并确认固件烧录的是本次构建产物。

## 13. 分阶段上电测试

### 13.1 第一阶段：空载、低速、单段

先只保留一个轨迹段，目标角度与当前角度接近，速度设置为低值，例如 `0.1f` 到 `0.3f` rad/s。确认：

1. 触发命令后 `Target_Point` 被更新。
2. 六个关节运动方向正确。
3. 电机没有异常响声或抖动。
4. 反馈角度能够接近目标角度。
5. 轨迹到达末尾后定时器停止。

### 13.2 第二阶段：逐段增加

一次只增加一个轨迹段。每次增加后确认：

- 上一段结束后能进入下一段。
- 进入下一段时没有突然跳变。
- 夹爪只在预期段发生动作。
- 当前段持续时间足够，电机能够到位。

### 13.3 第三阶段：完整空载运行

低速执行完整轨迹至少 3 次，记录：

- 每段实际开始和结束时间。
- 各关节最大误差。
- 是否出现目标点覆盖。
- 夹爪动作是否重复或漏动作。
- 轨迹结束后的最终姿态。

### 13.4 第四阶段：带载运行

确认空载稳定后再逐渐增加负载。带载时优先降低速度并增加 `time`，不要只提高电机力矩来掩盖轨迹时间不足。

## 14. 轨迹执行时序说明

`TrajectoryExecutor::update()` 的核心行为是：

1. 根据 `auto_traj_idx * period_ms` 计算当前时间。
2. 根据累计时间找到当前轨迹段。
3. 如果仍在同一段，不重复写 `Target_Point`。
4. 进入新段时，将六个关节目标点整体复制到 `Target_Point`。
5. 在自动模式下更新夹爪状态机。
6. 所有轨迹段执行完后，`auto_get_task()` 停止定时器。

因此轨迹段之间不是插值点流，而是“分段目标点”。每一段内，电机驱动器以该段的目标位置和速度运行。若需要真正的连续插值、加速度限制或笛卡尔空间规划，需要扩展 `TrajectoryExecutor`，不能仅通过增加几个数组元素实现。

## 15. 常见问题排查

### 问题 1：命令发出后完全不动

按以下顺序排查：

1. `Arm_Current_Control_Mode` 是否为 `Arm_Auto_Mode`。
2. `auto_get_task()` 是否已经启动。
3. `traj_timer_init()` 是否成功创建定时器。
4. `auto_traj_timer_id` 是否有效。
5. `auto_traj_idx` 是否递增。
6. 电机是否使能且 CAN 有反馈。
7. 新命令是否真正进入 `switch (cmd_req)`。

### 问题 2：轨迹只执行第一段

重点检查：

- 定时器回调是否被调用。
- 当前模式是否被其他任务切走。
- `time` 是否误写成过大的数值。
- `auto_traj_idx` 是否被其他代码清零。

### 问题 3：刚触发就跳到危险位置

通常是轨迹第一段与当前姿态差异太大。处理方法：

1. 增加一个与当前姿态接近的过渡段。
2. 降低第一段速度。
3. 增加第一段 `time`。
4. 先执行安全姿态，再执行目标动作。

### 问题 4：夹爪动作不正确

检查 `gripper_ctrl` 是否写在正确的轨迹段末尾，并确认轨迹处于 `Arm_Auto_Mode`。夹爪模式是在轨迹段切换时设置的，不是每 5 ms 重复发送一次。

### 问题 5：轨迹被手柄控制覆盖

说明控制模式仍是手动跟随模式，或者其他任务正在写 `Target_Point`。应统一控制模式入口，确保执行轨迹期间只有自动轨迹任务负责发布目标点。

### 问题 6：编译通过但新轨迹无法选择

编译通过只说明数据和符号正确，不代表触发链完整。确认以下链路全部存在：

```text
命令枚举
  -> auto_key_cmd_exec()
  -> cmd_req
  -> auto_get_task() 的 switch
  -> Auto_Switch_Group()
  -> traj_exec.update()
  -> Target_Point
```

## 16. 推荐的提交内容

增加一条正式轨迹时，建议一次提交包含：

1. `auto_traj_data.cpp`：新增轨迹数组和长度定义。
2. `auto_traj_data.h`：新增数组和长度声明。
3. `auto_keyboard.h`：新增触发命令。
4. `auto_get_task.cpp`：新增命令到轨迹的映射。
5. 触发入口文件：增加按键、遥控器或上层调用。
6. 本文档或轨迹说明：增加动作目的、关节表、测试记录。

建议提交说明中写清楚：

```text
轨迹名称：traj_demo
用途：演示取放动作
轨迹段数：4
总时长：8000 ms
夹爪动作：第3段关闭
测试状态：空载通过，带载待验证
```

## 17. 最小实现总结

新增一条可触发轨迹至少需要完成以下 6 件事：

```text
1. 在 auto_traj_data.cpp 定义轨迹数组。
2. 在 auto_traj_data.h 声明轨迹数组。
3. 在 auto_traj_data.cpp 定义轨迹长度。
4. 在 auto_keyboard.h 增加触发命令。
5. 在 auto_get_task.cpp 注册命令和轨迹的映射。
6. 从上层切换到 Arm_Auto_Mode 并调用 auto_key_cmd_exec()。
```

其中第 1 步决定运动内容，第 5 步决定能否被选择，第 6 步决定运行时是否真正推进。三者缺一不可。
